# `game_ui/static/` — frontend architecture overview (ES modules)

> **Contract: this file is the living map of the frontend.** Before any
> non-trivial change to the `game_ui/static/*.mjs` modules, read this file; after
> the change, update it in the same commit (new function / changed control flow /
> new message shape / new UI mode / renamed or removed function / new module /
> changed import graph). Trivial fixes (typo, debug line, CSS class tweak) do not
> require a doc update.

The frontend is a set of **vanilla ES modules** (no framework; `import`/`export`,
`"use strict"`). The entry point is **`app.mjs`**, loaded from `index.html` via
`<script type="module" src="/static/app.mjs">`. Importing `app.mjs` pulls the whole
dependency graph; `boot()` (in `setup.mjs`) wires the setup page and loads the card
pools. The old monolithic `app.js` was split into these modules — each file is now
self-contained and owns exactly one concern.

It drives the whole web UI of the game (served by `game_ui/app.py` on port 8001):
the setup/launch page, the game page (board, zones, trip chain, log) and the two-way
communication with the engine.

### Import graph (safe circularity)

The modules are **heavily cross-importing** and the graph is **circular** (e.g.
`game ↔ comm ↔ state`, `actions ↔ board ↔ zones`, `setup ↔ game`). This is safe in
ES modules **because no module reads another module's `const` at top level** — every
cross-module reference is inside a **function body** (evaluated lazily, after the
whole graph has finished evaluating). Top-level statements are limited to:
self-contained `const` initializers, DOM wiring in `modals.mjs` (the `<script>` is
deferred, so the DOM is ready), a `resize` listener in `log.mjs`, and the `boot()`
call in `app.mjs`. **Keep it that way:** if you add a top-level statement that reads
an imported `const`, you can hit a TDZ error — move it inside a function.

## Ground rules it mirrors from the engine

These invariants are **re-implemented client-side** — keep them in sync with the
engine (`engine/game_engine.py`) and with `game_ui/ai_driver.py`:

| Invariant | Where |
|---|---|
| Player message shape `{cards, to, mode, pendings[, cell]}` | `comm.mjs` `sendAction()` |
| Card cost = main card `mana`, support card `mana_cost` | `cards.mjs` `cardCost()` + `state.mjs` `checkMana()` |
| Stopover ordering: **PER-PLAYER** — each player has their OWN 5 positions (1..5, columns 4,3,2,1,0). A player's rooted cards occupy the leading positions of that player's chain (position 1, 2, …) and the player's plays (move OR defend) go AFTER the rooted cards (position R+1, …). A player's rooted cards NEVER shift the opponent's positions. **The dwelling placeholder ALSO consumes one position** (the engine increments `play_count` when the refinery is placed, and `playedCount()` counts it via `p.dwelling && p.dwelling_slot != null`) so the next play lands on the position AFTER the placeholder | `actions.mjs` `playedCount()`, `rootedCount()`, `nextPosition()`, `freeCols()`, `nextSlotCol()`, `canDropOnStopover()` — mirrors `ge._player_stopover` / `ge._player_chain` (engine = single source of truth; the robot calls it directly in `ai_driver.py`) |
| Only 1 or 3 cards per mana message during init → init sends one at a time | `actions.mjs` `dispatchPlay()`, `init-mana` branch |
| Hidden info: opponent only seen via `*_count` and masked ids — **the discard piles of BOTH players are PUBLIC** (only hand/mana/deck are masked by `current_game_json`) — that's what the discard-pile viewer shows | `zones.mjs` `publicCount()`, `renderOppZone()` (card backs); `modals.mjs` `showDiscardPilePopup()` (read-only pile viewer, no message sent) |
| Deck = 20 main + 10 support, shuffled together before sending | `setup.mjs` `launch()` (`shuffleDeck`) |
| **Deck rules** (20 mains, one faction, no duplicates, ≤5 per condition family — numeric variants merged, ≤5 per effect, no `face_point_*`) enforced at launch; the SERVER is the hard gate (`deck_rules.py` via `API.check_deck`) | `cards.mjs` `checkMainDeck()` + `setup.mjs` `renderDeckIssues()` / `updateLaunchBtn()` / `launch()` |
| Duplicate main card ids no longer rejected at import — they surface in the deck-issues panel and block launch | `setup.mjs` text-file `onchange` + `cards.mjs` `checkMainDeck()` |
| The faction buttons serve the **designer starter deck** authored in `cards/starter_decks/*.txt` (served by `API.py` `GET /starter_decks`); the seeded random build is a **fallback only** (list missing/unloaded, or invalid → one-shot toast) | `cards.mjs` `STARTER_DECKS`/`loadStarterDecks()` + `setup.mjs` `buildStarterDeck()` |
| Discard selection: `discard`/`discard_oppo` pause the chain — the discarding player picks exactly N hand cards, sent as `{cards:[…N…], to:"discard_pile", mode:""}`; only the discarding player may answer | `phase.mjs` `detectPhase` (`kind:"discard"`), `actions.mjs` **`showDiscardPopup(n)`** (hand-card grid + red DISCARD button at the bottom), `state.mjs` `renderAll` (auto-open + sweep), `interaction.mjs` `makeHandCard` (click = reopen the popup) |

## Card data helpers (single lookup path — `cards.mjs`)

All card display goes through these — **never** read `CARDPOOL` directly for a
card that might be a support card:

- `cardInfo(id)` → row from `CARDPOOL` **or** `SUPPORT`, or null.
- `cardTitle(id)` → human title (support cards show `card_name (⚙ faction) — description`).
- `cardImg(id)` → `/art/<card_path>` for support cards, `/art/<card_id>.png` for main cards (the file name differs from the card name for support cards — that's why this helper exists).
- `earthBgSrc(earth)` → the Earth background image for a game, **derived from the board's biome order** (`earth` = `state.earth`, the engine's `biomes_order`): cell 0 is at the top of the ring (clockwise — `POS24`), so segment 0 (cells 0–5) is the image's **top-right quadrant**; the four configs cover one starting biome each — `DE→cfg1, MO→cfg2, OC→cfg3, JU→cfg4` → `/assets/earth_cgf<N>_nomarker.png`. The starting quadrant is always correct; the whole board matches 4/4 when the cyclic order matches the asset (12 of the 24 possible orders — the assets only contain 2 cyclic classes). Falls back to `/assets/earth_background_playmat.png` (the default in `index.html`) when the board is unknown.
- `cardCost(id)` → `mana` or `mana_cost`.
- `cardName(id)` → short name.
- `effectLabel(id)` (in `log.mjs`) → pretty effect label for the log (`advancing +2`, `recoil 1`, …). Reads **`CARDPOOL` only** — a support card has no `effect` column, so `effectLabel` returns null and `supportLabel(id)` (reads `SUPPORT`) renders the neutral `⚙ <faction>` tag instead.
- `getFactionKey(factionName)` → short key ("Dwarves" → "Dwa") from the `FACTIONS` table.
- `dwellingPlaceholderSrc(factionName)` → `/cards_ex/placeholder_<key>.png` (faction-specific placeholder art for the dwelling card in the stopover row).
- `factionLogoSrc(factionName)` → `/assets/logo_<key>.png` (the faction logo used as the player token on the Earth ring; `null` if the faction is unknown).
- `STARTER_DECKS` (filled by `loadStarterDecks()`, which fetches `GET /starter_decks`) → faction key → the designer-authored 20 main card ids. Read-only display data: `setup.mjs` validates it with `checkMainDeck` before using it, and the server re-validates the deck at launch (`deck_rules.py`).

## The three launch branches (`setup.mjs` `launch()`)

| Mode | Request | Then |
|---|---|---|
| `ai` | `POST /create_game_ai` `{name, deck, **tutorial**}` (`tutorial.enabled` — tells the ROBOT to guarantee a main-faction card on the turn-1 trip chain, see *Tutorial showcase* in `game_ui/APP_OVERVIEW.md`) | straight into `enterGame()` |
| `create` | `POST /create_game` `{name, deck}` | shows the game id (copyable) + `startWaitingForOpponent()` → `enterGame()` when the 2nd player joins |
| `join` | `POST /join_game/{id}` `{name, deck}` | `enterGame()`; a **409** (already in the game, page reload) is swallowed if the player is present in `GET /game/{id}` |

`deck` is always the **shuffled 30-card mix** (20 main + 10 support) — the server validates it via `check_deck`.

Deck building (`setup.mjs`): `buildStarterDeck` (deterministic per name via FNV-1a
seed + LCG; rare cards weighted 1 vs 3; 20 unique main cards), `parseCsv` (extracts
card_ids from a text file — .txt, or comma/semi/tab separated — one card_id per line,
validates the `XXXn_hex` shape), `shuffleDeck`
(Fisher–Yates). Support deck: `buildSupportDeck` (in `cards.mjs`, 2× each of the 5
unique cards).

## Communication model (important!) — `comm.mjs`

- **WebSocket** (`/ws/{game}/{me}`) is the **only** action channel: `sendAction(cards, to, mode, pendings, cell, dayNight, tempChange, cataclysmOrder, rotation, swapWith)` → Promise. Sends are **serialized** through `pendingResolvers` (one outstanding request). Replies: a game state (applied via `applyState`) or a rejection `{success:false, message}` (toasted via `showServerMsg`). The optional 6th param `dayNight` (`"day"`|`"night"`) is sent as `msg.day_night` and is **only** used by the Mages' `Celestial_reversal` (the player fixes day/night for the rest of the game — `actions.mjs` `showDayNightPopup`); it is omitted for every other action. The optional 7th param `tempChange` (`"up"`|`"down"`) is sent as `msg.temp_change` and is **only** used by the Mages' `thermic_flux` (the player picks +4/−4 °C to change the planet temperature — `actions.mjs` `showThermicFluxPopup`); it is omitted for every other action. The optional 8th param `cataclysmOrder` (a 4-element list of biome codes, a **permutation** of `OC`/`MO`/`DE`/`JU`) is sent as `msg.cataclysm_order` and is **only** used by the Mages' `Apocalypticritual` (the player chooses the order of all 4 cataclysm biomes — `actions.mjs` `showApocalypticritualPopup`); it is omitted for every other action. The optional 9th param `rotation` (`'cw'`|`'ccw'`) is sent as `msg.rotation` and is **only** used by the Mages' `black_hole` **dwelling TAP** (the player chooses the direction to rotate the earth 3 cells — `actions.mjs` `showBlackHoleRotationPopup`); it is omitted for every other action (including the refinery/laboratory dwelling taps, which carry no `rotation`). The optional 10th param `swapWith` (an int 1..5) is sent as `msg.swap_with` and is **only** used by the **`swap_cards`** effect (the player swaps the card's trip-chain position with one of their OWN chain entries — a play, a board placeholder, or a rooted card — `actions.mjs` `showSwapPopup`); it is **optional** (omitted when the player plays without a swap) and ignored for every other action.
- **Polling** (`GET /api/state/{game}/{me}`, every 2.5 s) exists because the WS only *receives* a state when **we** send — polling is how we see the **opponent's** actions. Both feed the same `applyState()` funnel.
- **Auto-reconnect (host sleep/wake — e.g. Render free-tier spin-down, HF hibernation)**:
  - **Socket generation counter** (`wsGen`): every `connectWs` invalidates the previous socket's handlers — a stale socket's late `onclose`/`onmessage` can no longer flap the label, double-schedule a reconnect, or mis-resolve a reply (`isLive()` guard).
  - **In-flight actions never hang**: when the live socket closes, `settlePending()` resolves every queued action Promise with the rejection-shaped sentinel `{success:false, message:"Connection lost — the action may not have gone through"}` — awaiting UI (discard/defend popups re-enable their confirm button, the init-mana loop breaks) toasts and lets the player retry; the 2.5 s poll re-syncs the true state either way (the engine is the source of truth).
  - **Reconnect loop**: `setConn(false)` in-game shows `○ reconnecting…` and schedules ONE 2 s retry (the timer is cleared + replaced on every close, so there is never more than one pending retry); out of a game it just reports `○ disconnected` (no loop).
  - **`sendAction` while disconnected**: toasts `Connection lost — retrying…` **once per disconnect period** (not per 1.5 s retry), reconnects, and re-attempts the send every 1.5 s until the socket is OPEN — the action then resolves with the server's real reply. An `inFlight` guard per action ensures the resolver is queued at most once (no double-send / no mis-paired reply after a close-during-retry).
  - **`leaveGame`** (`modals.mjs`) calls **`teardownWs()`** instead of closing the socket inline: it bumps the generation, clears the reconnect timer, closes, and settles in-flight Promises — so leaving the game never leaves a reconnect loop firing with the old game id.
- `applyState()` is the single entry to rendering; there is no other path that mutates `game.state` or the DOM game view.

`applyState(st)` (single funnel for WS replies **and** poll responses): **snapshots
the old DOM zones for the card-movement animation** (see `anim.mjs`), exits
cell-select **only when the state actually changed** (content comparison
`JSON.stringify(oldSt) === JSON.stringify(st)` — the 2.5 s poll re-applies the
**same** state while the player is choosing an engineer-drop cell, and an
unconditional exit made the circle targets vanish within 2.5 s of entering the
mode — the “circles disappear before I can click” glitch), stores state,
`renderAll()` (in `state.mjs`), **flies the
zone-transition cards** (hand→stopover, stopover→discard, deck→hand, …), shows
server message, endgame detection.

`enterGame()` (in `game.mjs`): switch view, connect WS, start polling.

## Rendering invariants

- **Full re-render per state**: `applyState → renderAll` rewrites the zones, board rows and slots from scratch (the DOM is treated as a function of `game.state`). The exceptions are deliberately transient/incremental: the **log** (`game.logTurnsRendered` + `game.logTurnSigs`, `log.mjs` — new turns are appended, and a rendered turn whose **content changed** is re-rendered in place keeping its open/closed state; this is required because the engine creates a turn's log entry at PLAY TIME with only the `instant` section, and the same entry gains its stopovers when the trip chain resolves — the turn count does not change), the **selection/cell-select** UI, the **trip-chain animation** (its `.chain-anim-card` clones are spared by `renderBoard`'s slot wipe — `.played:not(.chain-anim-card)` — and torn down by `clearChainAnim` / the run's final step; `chainGen` invalidates pending timers, `chainanim.mjs`), the **player markers** (`.marker[data-player=…]` are repositioned across renders so their CSS left/top transition animates the advance — `board.mjs`; they can also be **visually pinned** to a cell that is *not* the player's `current_position` via `setMarkerOverride(name, cell)` / released with `clearMarkerOverrides()` — `renderBoard` draws from that override map, so a state poll cannot snap a pinned token back mid-replay; the override map is the only place a marker position can come from besides `current_position`, it is never written by anything but those two functions, and the marker tooltip then reads `… (replay — real: N)`), and the **card-flight clones** (`.card-fly`, self-removing, never part of the rendered state — `anim.mjs`).
- **Delegated hover**: card hover previews are wired on `document` (mouseover/mouseout + `.card[data-hover-id]`), not per element — required because re-renders destroy per-element listeners. New card elements **must** keep `data-hover-id`. (in `modals.mjs`)
- **Faction themes (per-faction colors, editable JSON)**: `static/faction_themes.json` holds each MAIN faction's UI palette (`accent` / `accent2` / `onAccent`, sampled from the faction logo) — **edit it and reload to change the colors, no code change**. `theme.mjs` sets three CSS variables per scope (`--accent`, `--accent-2`, `--accent-contrast`; opponent variant `--oppo-accent*`) and `style.css` derives **every** tint/glow/gradient from them with `color-mix()` (so a scope override cascades — there are **no hardcoded accent hex/rgba left** in the CSS except the `:root` default teal/orange fallback). Scopes: the **setup page** `#view-setup` (the selected faction's palette; hover previews), the **game page** `#view-game` (MY faction = page default via `syncGameThemes` in `renderAll`), the **opponent containers** `#oppo-zone` / `#oppo-side` / `#row-oppo` (THEIR faction's palette), and the opponent's **board marker** (`.marker.oppo` reads `--oppo-accent` set on `#view-game`). The page **background stays the dark blue** (`--bg-*`), and the mana-drop / tap / discard mechanic colors (purple / red) are intentionally NOT themed. `anim.mjs` `flyCard` copies the current `--accent` onto its body-level clone so the flight glow ring matches. (`theme.mjs` + `setup.mjs` + `state.mjs` + `style.css`)
- **Stopover slot watermarks**: every stopover slot contains the **row owner's main-faction logo** as a faint watermark (`.slot-logo`, built once in `buildBoard`, src set per row in `renderBoard` from `p.faction` via `factionLogoSrc`) — my row shows MY logo, the opponent's row shows THEIRS; hidden when the faction is unknown. Purely visual, behind the cards (z-index 0). (`board.mjs` + `style.css`)
- **Art fallback**: every `<img>` gets `onerror → /placeholder.svg`; support art via `cardImg()` (`card_path`), main art `<card_id>.png`. (helper `cardEl()` in `cards.mjs`)
- **Earth background = the board's biome configuration, ROTATED to match the black_hole**: `renderBoard` sets `#board-bg`'s src via `earthBgSrc(b0)` where **`b0` is the INITIAL cell-0 biome** (`game.state.earth_initial_b0`, fallback `game.state.earth[0][0]`) — pinning the base image to the **initial** order so it is stable across rotations. Then it applies a CSS **`transform: rotate(earth_rotation × 15deg)`** to `#board-bg` (the board geometry is 15° per cell — `POS24[i] = polar(-90 + (i+0.5) × 15°, 49)`), so the background artwork **rotates** (not swaps) to match the engine's biome positions after a `black_hole` tap (`game.state.earth_rotation`, the signed cumulative cell count; e.g. +3 after one CW tap → 45°). `style.css` gives `#board-bg` `transform-origin: center; transition: transform 0.6s ease` (the 0.6s transition animates the rotation on a tap). The src is only touched **when it actually changes** (the image is ~10 MB and the board re-renders on every state poll — a naive set would re-trigger the download each time); the `transform` is set every render (it is cheap and only animates when the value changes). `index.html` keeps the plain playmat as the pre-game/default src. (the rotation is verified visually via a before/after browser screenshot — the background art aligns with the biome segments after a tap). (`board.mjs` + `cards.mjs` + `style.css`)
- **Board tokens**: positions come from `POS24` (polar ring, radius 49 %, cell 0 at top, clockwise); stacks of trap/drop tokens fan up-right (`MAX_FAN`, `FAN_STEP_PX`) with a count badge on the top one. Drop tokens are **cleared and redrawn from state on every render** (`.drop-token` elements are NOT persisted — unlike the player `.marker`s): `renderBoard` removes the old ones before redrawing, so a token the engine **consumed** (a player stepped on it / jump-landed on it) disappears on the next poll, and polls don't stack duplicate images. (`board.mjs`)
- **Persistent board cards (survivors of the cleaning phase)**: three game-level / per-player fields render **outside** the `action_chain` into the stopover slots — the **dwelling placeholder** (`p.dwelling_slot`, a faction placeholder image in the slot the refinery/laboratory would have occupied, cleared by the engine in the cleaning phase), **pending placeholders** (`p.pending_slots`, the **per-turn placeholder list** — cleared by the engine in the cleaning phase, so it is **NOT parallel** to the persistent `p.pendings` zone; rendered with the **same faction-specific placeholder image as the dwelling cards** — `dwellingPlaceholderSrc(p.faction)` — with a gold border. Entry shape: **`[card, slot]` pair** (the laboratory TAP's `epo` = a `null` slot). The render loop and `playedCount()` normalize the shape and skip `null` slots. **the placeholder of a pending card attached the SAME turn STAYS IN PLACE** (the engine keeps the `[card, slot]` pair in `pending_slots` until the cleaning phase — it marks the consumed trip-chain position, so the next play lands one position further and `playedCount()` — which counts the non-null entries — stays consistent with the engine's `play_count`; the tooltip reads "attached to a card this turn" when the pair's card is an action's `pending_card`), and **rooted-on-board cards** (game-level `rooted_on_board: [{card_id, owner, stopover}]` — a card that earned a rooted token last turn survives on a stopover until the end of the NEXT turn). All three are rendered per owner row in `renderBoard` (stale elements are always removed first — the slots are built once, not rebuilt), all count as a **filled** slot, and none are part of the `anim.mjs` diff (they appear in place, no flight — same as the placeholder). The rooted card gets the green "stuck to the trip chain" frame + the rooted-token chip (`.rooted-on-board`, `.rooted-token` in `style.css`: a **circular dark-disc chip with the tree-with-roots icon + green ring**, top-right corner — a bare transparent PNG at the corner used to blend into the card art) and a `🌱 rooted — …` tooltip. **(per-player stopovers)**: the rooted card is a **normal card** on the trip chain — it occupies the **leading position** of its owner's chain (position 1, 2, …) and applies its **basic advancing** when the chain resolves (no condition, no effect, but **BLOCKABLE** by the opponent's defend at the same per-player position). The owner's plays go **AFTER** the rooted cards (position R+1, …), so the rooted card **consumes a slot** and the opponent's cards are independent (per-player positions never shift each other). **Per-player rule (the main path)**: a player's next position = `rootedCount(owner) + playedCount(owner) + 1`; column = `5 − position`. The rule is **per-player** (each player has their OWN 5 positions), so the two players' cards may legitimately share a column (e.g. both at `stopover_4`). **Single source of truth: `ge._player_stopover(game, name, played_before)`** in `engine/game_engine.py` (with `ge._player_chain`) — the engine uses it for its own placements (dwelling placeholder slot + rooted end-of-turn placement) and the robot calls it directly (`ai_driver.py`); the **frontend mirrors it in JS** in `actions.mjs` (`rootedCount`/`playedCount`/`nextPosition`/`freeCols`/`nextSlotCol` — it cannot import Python; the mirror was verified case-by-case against the engine). `canDropOnStopover` guards on `freeCols(st, me)`, the defend/Pass-area guards and the engineer-drop `confirmCell` guard do the same, and `orderHint` names the player's next position. **Layered slot (defensive fallback)**: a play and a rooted card can still share a column in old games (the shared-stopover model) — in that case `renderBoard` tags the rooted card `.behind` (smaller, nudged up, tilted, z-index 1 under the full-size played card) so the slot reads "your card on top, the last-turn survivor underneath" — and **re-parents the token chip to the slot** (class `.chip-float`, z-index 6) so it escapes the rooted card's low z-index and stays clearly on top of the played card (top-right corner); the render-loop cleanup removes both `.rooted-on-board` elements **and** any orphaned `.rooted-token` in the slot before re-adding everything. (`board.mjs` + `style.css`)
- **Player tokens show the faction logo**: each player's Earth token (`.marker`) renders the player's **faction logo** (`.marker-logo`, `factionLogoSrc(p.faction)` → `/assets/logo_<key>.png`) filling the circle, with the player's **first letter** on top (`.marker-letter`); the me/oppo gradient doubles as the fallback background when the logo is missing (unknown faction → letter-only circle). The marker element is persisted across renders (repositioned, not recreated — see above), so the inner HTML (logo + letter) is rebuilt on every render without affecting the left/top slide transition. (`board.mjs` + `style.css`)
- **Opponent masking**: never render opponent hand/mana/deck *contents* — counts (`*_count` or list length) and card backs only. (`zones.mjs`)
- **Mana-waiting glow**: `#dz-mana` gets the `.mana-waiting` class (a dark↔light-purple `drop-shadow` pulse, `@keyframes manaPulse` in `style.css`) **only** while the phase is `init-mana` or `mana-pass` — toggled in `renderMyZone` from the same `canMana` gate that enables the drag target, so it lights up exactly when a card may be dropped into the mana zone and is removed on every other phase (re-renders are idempotent: `classList.toggle(..., canMana)`). Purely visual. (`zones.mjs` + `style.css`)

### Card-movement animation (`anim.mjs`)

Because `renderAll` rewrites the DOM from state, cards would otherwise pop between
zones; this layer diffs the **previous** and **new** state per player and flies a
lightweight clone (`.card-fly`) from the old zone rect to the new one. Functions (in
order): `layoutRect(el)` (the hand-card rect with the element's current **computed**
transform translation subtracted — `getBoundingClientRect()` includes inline transforms
*and* in-flight/frozen transitions, so the snapshot must record the LAYOUT position to
stay correct when the flip transition is delayed or frozen — see the 2026-09-24
glitch entry in the change log), `snapshotZones()` (captures the CURRENT hand-card
rects (via `layoutRect`) + occupied stopover rects **before** `renderAll` — called
from `applyState`), `planPlayerMoves(oldP, newP,
isMe, player)` (set-diff of the public `action_chain` → hand→stopover (new plays) &
stopover→discard (cleaning / mid-chain-win flush); dwelling place/wreck; my hand
diffed by **id** (drawn / played / discarded / to-mana), the opponent's by **counts**
(card backs) since the hand is masked; a mana increase with no matching hand loss =
ramp (deck→mana), a mana decrease = taxation (mana→discard); a discard decrease + deck
increase = reshuffle), `sourceRect` / `destRect` (resolve a move to concrete rects —
live DOM for destinations, the pre-render snapshot for sources; **ID GOTCHA: the
stopover rows are `#row-me` / `#row-oppo` and `slotEls.me` / `slotEls.oppo`, while the
zone panels are `#my-*` / `#oppo-*`** — the two row ids differ), `flyCard(fromRect,
toRect, cardId, delay)` (fixed-position clone, 2×rAF then a CSS transform/opacity
transition; `FLY_MS=520ms`, stagger `FLY_STAGGER_MS=110ms`; removed after; face-down
variant `.card-fly.back` for the opponent), `flipMyHand(snap)` (FLIP: the remaining
hand cards slide to their re-centered position instead of jumping; 2026-09-24
robustness: a card is never re-flipped within 900 ms (`lastFlip` map) and a fallback
timer clears transform + transition even if the double-rAF never fires — so a delayed
or skipped frame can no longer leave a stuck transform that re-triggers the slide on
every poll),
`popNewBoardTokens` (new pet-trap / engineer drop tokens get the `.token-pop`
animation), `animateZoneTransitions(oldSt, newSt, snap)` (orchestrates: my flights
first, priority order plays → zone shuffling → draws). Constants: `FLY_MS`,
`FLY_STAGGER_MS`, `REDUCED_MOTION` (skip all flights under `prefers-reduced-motion`).
Purely visual — no state, no messages, no engine coupling. **Known approximation**:
when several engine actions land between two observed states (fast polling gaps), the
diff attributes the net change (e.g. a mana increase with no matching hand loss flies
deck→mana instead of hand→mana); the zone counts always end up correct because they
come from the state, only the flight's origin may be a generic back.

### Trip-chain resolution animation (`chainanim.mjs`)

`playChainAnim(t)`, `placeThread(col, firstRow)`, `clearChainAnim()` + `chainGen`
(generation counter). Triggered from `renderLog` when a **genuinely new** turn log
entry appears (`added && start > 0` — never on the first render/rejoin): the stopover
slots pulse in the **exact resolution order** read from the public turn log (the
engine appends the log's stopovers in resolution order and each entry carries `order`
1/2 = first/second player of the turn): stopover by stopover, first player's card
(gold, `chain-first`) then second player's (silver, `chain-second`), ~460 ms per card.
A glowing thread (`.chain-thread`, gold end on the first player's side via
`first-top`/`first-bottom`) bridges the two facing slots while a stopover has both
players' cards. Because the cleaning phase already cleared `action_chain` in the new
state, the played cards are **cloned** onto the slots for the duration of the run
(`.chain-anim-card`, keeps `.played` for layout + `data-hover-id` for the delegated
hover preview) and removed when the run ends. `clearChainAnim()` bumps `chainGen` so
pending `setTimeout(step)` calls are dead on arrival, and removes all pulse classes /
threads / clones. `renderBoard`'s slot wipe uses `.played:not(.chain-anim-card)` so
clones survive mid-run polling re-renders. Purely visual — no state, no messages, no
engine coupling.

**Hold mode + step API (for the tutorial's card-by-card replay).** `setChainAnimHold(true)`
(`tutorial.mjs` calls it on `startTutorial`, `false` on `endReplay`/`stopTutorial`) makes
`playChainAnim(t)` **only place the clones and return** — no timer, no automatic pulse run —
and `pulseStep(row, col, first, pairRow)` then lights exactly one facing pair with the
sustained `.chain-live` styling (`.slot.chain-live` = the infinite variant of the 460 ms
`chain-pulse`, `.chain-thread.chain-live` = the thread kept at full opacity) while the tip is
being read; `clearPulse()` / `clearChainAnim()` take it down. `unlight()` selects
`.slot.chain-live, .slot.chain-pulsing` (both classes, so a slot that lost one of them can
never keep a stale glow). The clone placement is factored into `placeChainClones(t)`
(idempotent: it skips a card already cloned on that slot). Note that `renderLog` deliberately
does **not** animate the **first** rendered turn (`added && start > 0`) — turn 1 of a fresh
game is that turn — which is why the tutorial calls `playChainAnim(t)` itself when its replay
starts: without it every resolution tip would frame an empty slot.


### Grab droplets (`droplets.mjs`)

Grabbing a card of MY hand **sheds a few faction-colored pixels** that fall to the
floor like droplets. One call site: `interaction.mjs` `makeHandCard` (the interactive
branch) → **`attachHandDroplets(el)`**. A left `pointerdown` (which is BOTH the
click-select and the drag start) bursts **`BURST = 6`** pixels at the cursor; while
the card is dragged it drips **`DRIP = 1`** every **`DRIP_MS = 130 ms`** (native HTML5
drag suppresses pointer events, so the trail position comes from a **document
`dragover`** listener — installed once, lazily, on the first wired hand card, never at
top level). Right-click (zoom) is excluded (`e.button` guard).

- **Physics**: one `requestAnimationFrame` loop drives every live particle (dt-clamped
  at 50 ms, so a backgrounded tab cannot teleport them): gravity 2300 px/s², lateral
  drift + spin, the **floor** = `innerHeight − 8`, one small bounce (restitution .3) then
  it sticks, flattens (`scaleX↑ scaleY↓`) and fades over 260 ms; the element removes
  itself (hard `MAX_AGE = 3.2 s` safety). `MAX_LIVE = 80` caps the count.
- **Color** = MY faction: `myAccent()` reads the **resolved `--accent`** of `#view-game`
  (set by `theme.mjs` from `faction_themes.json`) and copies it onto `#fx-layer`, because
  the layer is appended to `<body>` — **outside** every themed scope (the `:root` default
  is still teal, so reading the layer's own variable would give the wrong color). Same
  pattern as `anim.mjs` `flyCard`; `.droplet`'s `background` + glow `box-shadow` then
  resolve it, and a third of the pixels get `filter: brightness(1.45)` for sparkle.
- **Render-safe**: the pixels are **not part of the rendered state** (like `.card-fly`) —
  one lazily-created `#fx-layer` (`position:fixed; inset:0; z-index:84; pointer-events:none;
  overflow:hidden`; reused if it already exists), and each pixel's **first transform is
  written at spawn time**, not in the rAF loop (otherwise it flashes at the layer's
  top-left corner for one frame — the same rule `bg.mjs` follows). `renderAll` re-creates
  the hand cards every state, so the listeners are per element and die with them — no
  global accumulation.
- `REDUCED_MOTION` (imported from `anim.mjs`, read inside the function, never at top
  level) → **no particle at all**. Purely visual: no state, no message, no engine coupling.

## Quick in-game tutorial (`tutorial.mjs`) — opt-in coach marks

**Switch**: the setup-page checkbox `#chk-tutorial` ("I want to activate the quick ingame
tutorial", in `.launch-row` next to **Start**, **checked by default**) → `tutorial.enabled`
→ `game.mjs` `enterGame()` calls `startTutorial()`. Nothing else reads it; leaving the game
(`modals.mjs` `leaveGame`) and the end of the game call `stopTutorial()`.

**It is a pure READ-ONLY overlay**: no message is ever sent, `game.state` is never mutated,
no render function is modified. It reads `game.state` + the live DOM and positions
`position: fixed` divs it owns (`#tu-layer`, created lazily on first start).

**Feed**: `renderAll` ends with `tutorialTick()` (state change) + a 500 ms interval (element
moved / popup opened). Both call the same idempotent `tick()`, wrapped in a `try/catch` that
`stopTutorial()`s on a bug — a broken tutorial can never break `renderAll` or `enterGame`.

**Flow control** — `SEQ` is a linear list of step descriptors (`STEPS.slice()` at start;
`doneIds` remembers what finished). On every tick: if a step is showing, an `act` step whose
`auto(c)` is true closes itself; otherwise the scan walks to the first unfinished step and —
`expired(c)` → mark done **silently** (the moment passed: a player who never used the mana
phase, a rejoin on turn 5 …), `when(c)` → show it, else **wait** for the next state — and while
it waits `sync()` **hides the layer**, so a finished tip never stays frozen on screen
(OK would look dead); it reappears on the tick where the next moment arrives. The last
step also carries `expired: turn > 3`, so a run always terminates. The sequence can
therefore never wedge, never repeat and never leave a ghost overlay. A step can additionally
carry **`enter(c)`** (run once when it is displayed — attach a visual) and **`onDone(c)`**
(run when OK closes it; a returned number of ms becomes `moveHoldUntil`, a delay during which
no new tip appears — used to let a token slide finish).
**The resolution replay** (`resolve-intro` + `expandResolution()`). The engine resolves a
whole turn in **one** message, so when the client first sees the turn log both tokens already
stand on their final cells: reading about the chain would be reading about something invisible.
So when `resolve-intro` finishes, `expandResolution()` splices a **pair of generated steps per
card actually played in turn 1**, in the engine's real resolution order (the turn-1 log entry's
`stopovers` → `entries`, first player's entry first):

1. a **card step** — frames that card's own slot (`slotEls[row][col]`, `col = stopover_N % 5`),
   shows its art and narrates the real outcome from the log entry: mana cost + shield, the
   play-time **instant** lines of that card (`t.instant`), **1. block check** (the facing
   defense's shield total vs the card's cost, blocked/not blocked), **2. condition**
   (+ ✓ met / ✗ not met), **3. effect** (+ not applied / canceled), **4. basic advancing**
   (card value, the **+1 faction biome** bonus computed from `st.earth[pos_before]` ×
   `FACTION_BIOMES`, or "only cost − 1" when ✗) and a highlighted **`Total advancement:
   cell A → cell B = +N`** (`.tu-total`) — plus the entry's `negatives`/`notes`. Card wording
   comes from `modals.mjs` `cardLegend()`, the numbers from `cards.mjs` `cardInfo`/`cardCost`
   (a card id absent from the served pool degrades to the log numbers only, never to 0).
2. an **Earth step** — frames `#board-stage`, pulses that player's token (`.tu-marker-hi`) and
   announces the move in words (`cell 4 (Desert) → cell 7 (Jungle) — total +3`, the `jump`
   skip-the-in-between-cells note, or *why nothing moves*: blocked / canceled / clamped at
   cell 0). **The movement is the OK itself**: the step's `onDone` calls
   `setMarkerOverride(player, pos_after)` and returns `MOVE_HOLD_MS` (900 ms), during which
   `tickInner` keeps the layer off screen so the slide (450 ms CSS transition) is actually
   seen, then the next tip appears. Defense plays get no Earth step (they never move a token).

`enter`/`onDone` are generic step hooks: `show()` calls `step.enter(c)` once per display (the
card steps use it for `pulseStep(row, col, first, pairRow)` — the pair stays lit through
**both** of its tips — the Earth steps add the marker pulse; the turn's cards are cloned onto
their slots once, when the replay starts) and `advance()`
calls `step.onDone(c)` when OK closes the step, taking its return value as the hold delay; both
are individually `try/catch`ed. The replay's view state is bounded in three places: the intro
step's `enter` pins both tokens to their chain-start cells (`pos_before` of each player's first
entry) and starts hold mode, the `log` step's `enter` calls `endReplay()` (unpin + `clearPulse`
+ `setChainAnimHold(false)`, which also removes the clones), and `stopTutorial()` calls
`endReplay()` too — by then the replayed position equals the real one, so nothing jumps. A page
reload mid-replay drops the overrides (self-healing: the tokens return to their real cells).

**Two step modes**

| Mode | Shade | Exit |
|---|---|---|
| `info` (default) | the 4 shade rects **capture clicks** — the page is paused while the player reads | **OK** only (`Enter`/`Space` = OK; `Esc` deliberately does nothing) |
| `act` (`mode:"act"`) | `#tu-layer.tu-act` → shade `pointer-events:none`: the darkening is visual only, the player **really** drags the cards / clicks Pass (those controls must stay live, otherwise the step could never complete) | self-closes when `auto(c)` (e.g. `me.mana.length >= 3`, `action_chain.length > 0`, `!myTurn()`) or when `expired(c)` |

**ONE control**: the tip's footer holds a **single button — `OK`** (its label can change, e.g. **Finish** on the last step) and it is the only
`<button>` in `#tu-layer`. There is deliberately **no** skip / hide / end control: on an `info` step the shades swallow every other click, so OK is
the only clickable button on the whole screen.

**Spotlight geometry** (`sync()`): the target comes from `step.el(c)` **re-queried on every
sync** (re-renders replace hand cards, so nothing is cached), then 4 `.tu-shade` rects are
laid out around `rect ± step.pad` (default 10 px; 26 for `goal` so both ring-edge tokens are
inside) and a pulsing `.tu-halo` frames the hole. **The hole itself is never covered** — that
is why the darkening is 4 rects instead of one full-screen div with a `box-shadow` hole. The
tip goes on the side with the most room (`bottom/right/left/top`) and `.tu-arrow` (a **layer
child**, not a `::after`, which would raise a horizontal scrollbar inside the scrollable card)
points at the target; the arrow hides and the tip becomes a **bottom sheet** under 760 px.
No/zero-size target → full-page shade + centred tip, no halo.

**Steps** (`STEPS`, 15 static): 1 goal (`#board-stage` + the inline 🏁→🏆 SVG) · 2.1 trip
chain (`#stopovers`) · 2.2 hand · 2.3 mana zone (`#dz-mana`) · 2.4 discard panel · 3 **card
anatomy** (`.tu-anatomy`: the chosen hand card's own art with 6 numbered hotspots + legend —
mana cost / basic advancing / shield / condition / effect / faction biomes; the positions
mirror the printed frame: left column = cost, advancing, shield, bottom strip = condition |
effect, and the two biome icons flank the name; the card is picked to maximise the visible
elements) · 4 the 3 planet cards (`#env-cards`) · 5 `act` init 3 mana · 6 `act` first play
(its text adapts: first/second player, whether the opponent already played, the actual
available mana) · 7 `act` more-or-Pass (**only after the player's own first card of the turn** —
`when: turn===1 && myPlayTurn(c) && playedThisTurn(c)` — so OK-ing step 6 never stacks a second
"your move" tip on the board; it points at the next slot or at `#btn-pass` depending on
`manaAvail` vs the cheapest hand card) · 8 `resolve-intro` + **the replay**: per card of the
turn a **card step** (its slot, the 4 engine checks, the total advancement) followed by an
**Earth step** (`#board-stage`, OK = the token slides) ·
9 log (`#log-panel`; its `enter` ends the replay) · 10 cleaning (`#topbar`) · 11 `act` mana
phase · 12 the 3 support factions (targets a support card in hand; button label **Finish**).

**Layering** (z-index): shades/halo **62** < `#card-hover` **66** (a hover preview inside the
spotlight must stay readable) < `#toast` **70** (an error toast must be readable over the
tutorial) < tip **72**. Two rules make the overlay coexist with the page:
`popupOpen()` (`.modal:not(.hidden)` / a pending-defend-discard-swap popup, z-index 50 → below
the layer) → the layer adds `.tu-mute` (`opacity: 0` + `pointer-events: none` on shade, halo and
tip) and comes back by itself when the popup closes, so a mandatory game popup is never covered; and
`body.tu-on #stopovers { z-index: 2 }` raises the trip chain above the absolutely-pinned
`#log-panel` (position absolute, `z-index: auto`), which overlaps the right end of the
chain: **measured** at a 1414 px window, `elementFromPoint` at the centre of two stopover
slots returns `#log-body` without the rule and the slot itself with it — otherwise a
spotlight on stopover 1 would frame the log text instead of the slot, and the halo would
sit on an element the player cannot even hit.

**A step may be gated on the action of the previous one**: `playedThisTurn(c)` is
`(me.action_chain || []).length > 0` — the engine's own per-turn play list, cleared in the
cleaning phase (so it never leaks across turns) and covering move **and** defend plays. Step 7
uses it as `when`, which is what makes "Spend the rest, or Pass" arrive after the first card
instead of on top of it. **Whenever a `when` is tightened like that, `expired` must also cover
"the moment is over"** (`turn > 1 || resolvedTurn(c)` here): the linear scan stops at the first
step that is neither done nor eligible, so a step that can never become eligible any more would
otherwise block every step behind it.

**Never wedges the game** (and OK is enough to walk it): a step is shown only while its
`when(c)` holds, a step whose moment passed is marked done **without ever showing** (`expired`),
the layer steps off screen while the next moment has not come, and the last step expires after
turn 3 — so one OK at a time always reaches the end of the run, `game over`/`leaveGame` stop it
from the outside, and a slow reader keeps all the time they want (nothing auto-dismisses a tip;
the only timer is the 500 ms reposition/eligibility tick). Because there is no skip control, a
step can never be lost by mistake — and never re-shown either (`doneIds`).
