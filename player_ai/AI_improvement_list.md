# Robot (AI) — Check-up & Improvement List

> Date: 2026-09-21. Scope: `player_ai/playerai.py` (`PlayerAI`) + `game_ui/ai_driver.py` (`ai_decide`, `run_ai_loop`).
> This is an **audit only** — nothing has been changed yet. Items are tagged with priority:
> **P0** = user-visible gap (the robot ignores whole card families / plays badly), **P1** = clear strength gain, **P2** = polish / robustness.

## How the robot works today (baseline)

- `ai_driver.run_ai_loop` polls the DB every 0.4 s and calls `ai_decide`, which dispatches on the state string:
  - init phase → `put_mana(3)`; mana phase → `put_mana(1)` or pass; discard-selection pause → `choose_discard`; play phase → `play_card` (move) with a random-50 % reaction to `defend_card`.
- **Every support card in hand is dead weight**: `play_card`/`defend_card` filter by `ge.CARDS_DB` (main pool only), so the robot never plays an Engineer drop/dwelling, Doctor pending/laboratory, or any Mages card — it burns them into its mana zone first (`put_mana` ranks support cards *first* for that purpose).
- Card scoring is `(condition_met?, advancing)` — nothing else. No endgame logic, no effect values, no block awareness, no cost model (a not-met condition only advances `mana − 1`, which the score ignores), no biome bonus (+1) modeling.
- Defense: at most **one** defend card per turn, offered with a flat 50 % coin flip *only after* the robot has already moved this turn, highest-shield affordable card regardless of whether that shield actually wins the block race (`Σ shields ≥ opponent mana cost`).

## A. Support-faction support (the main request) — P0

### A.1 Shared infrastructure (prerequisite for all three factions) — ✅ DONE (2026-09-21)

**Status:** implemented in `player_ai/playerai.py` + `game_ui/ai_driver.py`; verified by `tests/_ai_support_infra.py` (89 checks: 3 real games driven through `ge.handle_websocket_message` with the real `ai_decide`, plus unit checks of every message builder and validator). All 15 support cards can now be played LEGALLY by the robot:

- **#1 Card-model unification** — `PlayerAI.__init__` builds `MAIN_ROWS` (O(1) pool lookup by `card_id`) + `SUPPORT_INFO` (`card_name` → faction/cost/kind, kind ∈ move/drop/dwelling/pending/instant). Main cards keep the existing `play_card` path; support cards flow through the new `choose_support_play()` fallback. Defend never uses support (no shield value).
- **#2 Message contract** — `build_support_message(name)` returns a complete engine-valid message per card: drops get `cell` (`_choose_drop_cell`: boost/trampoline 1–6 ahead of my token; gluetrap/landmine on the opponent's near path), dwellings `to:"dwelling"`, pendings `to:"pending_zone"`, Celestial_reversal `day_night`, thermic_flux `temp_change`, Apocalypticritual `cataclysm_order`; `tap_dwelling()` builds the free quick-action tap (`rotation` only for black_hole); `play_nobodymoves_threat()` is the threat-only entry point.
- **#3 Pre-validation** — module-level `validate_message(msg, dwelling=...)` mirrors `ge.message_check` + all support field requirements; `run_ai_loop` gates every outgoing message through it (invalid → fallback pass, never submitted).
- **#4 Quick-action bookkeeping** — `st['tapped_this_turn']` in the loop's phase dict: set on a tap decision, cleared on phase change / rejection / exception so a rejected or new-turn tap can be retried; exactly one tap per turn is guaranteed.
- **#5 Action priority (implemented order)** — per tick in the play phase: **1. dwelling tap** → **2. nobodymoves threat response** (only before I have declared my own move this turn) → **3. defend reaction** (kept at its current position: only AFTER I already moved, preserving today's anti-deadlock invariant; §D refines it) → **4. main move card** (`play_card`, now returning `None` instead of a forced play when nothing is playable/affordable) → **5. support fallback** (`choose_support_play`) → **6. pass**. Stopover for every move/defend/support-play = `ge._player_stopover(game, name, me.play_count)` — the engine's own counter (counts moves+defends AND pending/dwelling placements; the old action_chain-derived sum under-counted).
- **#6 put_mana** — replaced the "support-first" sacrifice with a keep-value model: `_mana_keep_value` = `18 − mana` for mains, `_support_value(card)` (current play utility) for support → playable support stays in hand; dead copies (2nd dwelling with zone full, useless instant…) and expensive mains sink to the bottom.
- **Also landed** (used by all three factions): `update_player_state` now captures public board info (`earth_biomes[24]`, `cataclysm_pile`, `day_night_fixed`, `occupied_cells`, opponent faction) — this is what makes the §B.19 `biome_*` fix and the §A.3/A.4 choices possible.
- **Baseline choice functions** (first versions of #11–#17; all refined since: **#11–#15 in A.3, #16/#17 in A.4**): `_choose_day_night` (#11), `_choose_temp_change` (#12), `_nobodymoves_threat` (#13 — a three-part public threat estimate with self-deny guard, declared-threat scoring and latent pool-curve check), `_choose_cataclysm_order` (#14 — exact 24-permutation knockback model), `_choose_rotation` (#15 — faction-bonus + `biome_*`-mains weight), `_choose_drop_cell` (#16 — path-aware targeting with arrival-first and self-harm checks, see A.4).

**Still open in the A-section:** #8 attachment policy (a main move card is never sent with `pendings: [name]` yet — pending cards sit unused in the zone), plus all §A.2–#4 refinements.

3. **Pre-validate outgoing messages** *(P1)*. Mirror `ge.message_check` locally before submitting (especially the required choice fields above). The loop's rejection fallback currently just passes next cycle; better to never emit an invalid message in the first place.
4. **Quick-action bookkeeping in `ai_decide`** *(P0, implementation trap)*. Dwelling taps do **not** alternate control → state stays `"waiting for <robot> to play"` across ticks. Without a per-turn local flag (e.g. `st['tapped_this_turn']`, reset with the phase key), the robot will re-send the same tap every 0.4 s and get rejected (`dwelling_tapped`).
5. **Action priority inside the play phase** *(P1)*. With new action types, define an explicit per-tick order that preserves today's "always make progress" invariant (the loop's anti-deadlock property), e.g.:
   1. tap own dwelling if placed & untapped (free — do it before anything else; for `black_hole` the rotation changes which biome is under each token, affecting `biome_*` conditions of cards that resolve **later this same turn**),
   2. threat response (`nobodymoves`, see A.3),
   3. main move card (with best pending attachment, see A.2),
   4. support plays (drop placement / pending placement / dwelling place) if mana remains and expected value > playing nothing,
   5. defend reaction (see D).
6. **`put_mana` must change with it** *(P0, contradiction)*. `put_mana` currently prefers **support cards first** as mana tokens ("the robot never plays them"). Once the robot *does* play support cards, burning them into the mana zone destroys their effects forever (mana-zone cards are never recycled except via taxation). New rule: value each hand card by (expected utility of playing it) vs (1 free mana token), e.g. keep playable main + useful support in hand; put to mana the least-valuable **main** cards, and only surplus/unusable support duplicates once their effect is on board already (a 2nd `refinery`/`black_hole`/`laboratory` copy is worthless — one dwelling slot).

### A.3 Mages — ✅ DONE (2026-09-21)

**Status:** all five choice functions refined from their A.1 baselines in `player_ai/playerai.py`; verified by `tests/_ai_a3_mages.py` (37 checks: every policy branch as unit scenarios on synthetic public state + a real game through `ge.handle_websocket_message` where the threat-aware keep-value keeps nobodymoves out of the mana zone at init and the robot plays it as its FIRST action of turn 1 against an opponent standing on cell 20). All estimates use public info only (positions, board layout, global phase/temperature/pile, my own zones, the opponent's declared `action_chain` + visible counts).

- **#11 Celestial_reversal** — `_choose_day_night` now weights by **value**, not raw counts: each own day/night main in hand+deck contributes its condition delta (`advancing − (mana−1)`), so two junk phase cards no longer outvote one valuable one; the card is only played when the preferred phase strictly beats the current one AND it would change something (already-fixed-to-preference or neutral → kept). `_condition_met` still re-reads `game.day_night` every tick.
- **#12 thermic_flux** — `_temp_weight(t)` sums the value delta of every own `temp_*` main met at candidate temperature t; `_choose_temp_change` compares W(cur+4 clamped) vs W(cur−4 clamped) and plays ONLY on strict improvement (at the clamp edge both directions can be no-ops → the card stays in hand). Opponent-side effects remain ignored under fair play.
- **#13 nobodymoves** — `_nobodymoves_threat` is now a three-part public estimate: **(a)** self-deny guard first — if any affordable main in MY hand could win this turn (`_move_estimate ≥ 24 − pos`, mirroring the §C advance model), never lock myself out; **(b)** declared threat — each of the opponent's UNRESOLVED move plays (public `action_chain`) is scored with `_oppo_potential_adv` (condition evaluated from public info via `_oppo_condition_eval`: day/night, temp_*, biome_X at their cell, dist_* from THEIR perspective; unknown → worst case for me), plus the faction-bonus at their cell, minus MY declared shields on the facing stopover (`_my_shields_at`) — except `unstoppable` cards whose condition is provably met ignore my block; **(c)** latent threat — `_min_win_cost(need, bonus)` (precomputed over the whole pool: cheapest card that could cover the remaining distance) vs the opponent's VISIBLE spending power this turn (`oppo_mana − visible mana_spend`, both public). `nobodymoves_active` already on → no second copy. The keep-value side (`_support_value`) uses the same estimate, so a held nobodymoves survives init/mana sacrifice while a real threat is live.
- **#14 Apocalypticritual** — two gates: `_cataclysm_soon()` (an affordable cataclysm-condition main in hand OR my own already-declared unresolved cataclysm play — otherwise the reorder has no near-term value) and strict improvement. The order itself is scored EXACTLY over all 24 permutations by `_pile_value`: a strike knocks every token on that biome back to its segment's first cell, so one strike at slot i is worth `weight_i × (opponent_knockback − my_knockback)` cells with earlier strikes weighted more (`_biome_knockback` reads both tokens' positions + the public board layout). This handles shared biomes (deep-vs-shallow decides whether to strike early or park late), empty biomes, and segment depth uniformly — replacing A.1's fixed "opponent biome first, mine last" candidate.
- **#15 black_hole** — `_choose_rotation` scores each direction by (i) the faction-biome bonus each token keeps after the rotation (mine worth 2×, opponent's subtracted — as in A.1) PLUS (ii) `0.5 × _biome_cond_weight(biome under my new cell)`: the value delta of every own `biome_X`-condition main that would become met/unmet at my landing cell (`BIOME_COND_FACTION` maps biome → faction). Ties → cw.

Left for §C: sequence-aware scoring (a flux/celestial played THIS turn should re-project later plays, #20), and opponent modeling (#38) to sharpen the latent-threat estimate further.

11. **`Celestial_reversal`** *(P0)*. Cost 2, permanent. Choice heuristic: the robot knows its full own hand+deck (`player_state.hand` + `player_state.deck`) → count `day`- vs `night`-condition cards in hand+deck (and weigh by value) and fix the phase that makes more of them met; also consider *current* day/night (fixing the current one is "free" for this turn's plays). Once either player plays it (`game.day_night_fixed == True`) the flip stops — `_condition_met` already re-reads `game.day_night` each tick, so no extra work.
12. **`thermic_flux`** *(P0)*. Cost 2, permanent ±4 (clamped 1–20). Heuristic: for each direction compute how many own `temp_inf_6 / temp_inf_11 / temp_sup_9 / temp_sup_15` cards in hand+deck would be met at the resulting temperature; play toward the better side. Note both directions change *opponent* conditions too (unknown deck — ignore under fair play).
13. **`nobodymoves`** *(P0)*. Cost 3, defensive: locks all movement for the rest of this turn (both players; only unstoppable+met moves; non-movement effects like draw/ramp/discard/taxation/rooted still fire, block race still happens, cataclysm knockback suppressed). Play it when **the opponent is threatening to win this turn** — e.g. `oppo_position + estimated_best_oppo_advance ≥ 24` (estimate from public info only: position, hand count, cards they've played before; the robot does not see their hand). Do NOT play it while I am myself within winning distance (it locks me too).
14. **`Apocalypticritual`** *(P0)*. Cost 3, permanent until next ritual. The pile's index-0 biome strikes on the *next* `cataclysm`-condition card resolution and knocks back **all tokens** standing on that biome to its first cell (both players!). Heuristic: build a permutation putting (a) the biome under the **opponent's token** at index 0 (public info: `game.earth[oppo_position][0]`), (b) the biome under **my own token** as far back as possible, keeping the remaining biomes in current order. Re-evaluate only when I actually hold/expect a cataclysm card to resolve soon — otherwise the reorder has no near-term value.
15. **`black_hole`** *(P0)*. Cost 3 dwelling; tap (free, once/turn) rotates the earth ±3 cells: biomes shift, tokens stay on their cell index → changes which biome is under each token (and thus `biome_*` conditions + the +1 faction-biome bonus). Heuristic per tap: simulate both directions (`earth[(pos ∓ 3) % 24][0]`) and pick the one that puts **my** token on a home biome of my faction (`FACTION_BIOMES[my_faction]`, public via `player_state.faction`) while ideally taking the opponent off theirs. Rotation is cumulative (8 distinct offsets) — with a free tap per turn the robot can "track" its own position and stay on-bonus nearly every turn, which compounds with §C biome-bonus scoring.

16. **Drop placement** *(P0)*. `boost`/`trampoline` (cost 1) and `gluetrap` (cost 1), `landmine` (cost 3): move-mode play + chosen `cell`. The drop fires on the **first arrival** of any token, then is consumed; a jump lands-and-triggers; knockbacks don't trigger. Heuristics:

17. **Refinery** *(P0)*. Cost 3 dwelling, tap (free) = draw 1 per turn → card advantage + hand refill for the next turn's plays. Place as soon as affordable and not needed as mana economy; always tap each turn (#4 bookkeeping).
18. **Dwelling choice vs wrecking_ball** *(P2)*. ## B. Condition evaluation (`PlayerAI._condition_met`) — P0/P1 — ✅ DONE (2026-09-21)

**Status (all three items resolved):**
- **#19 FIXED** — `biome_*` is now evaluated in `_condition_met` as an **exact engine mirror from public info only**: met iff the biome of my cell (`earth_biomes[current_position]`, captured by `update_player_state`) ∈ `FACTION_BIOMES[BIOME_COND_FACTION[condition]]`. Unknown `biome_*` names fall through to the permissive MET default (the engine's canonical catch-all), and a missing board layout degrades conservatively to not-met. The mirror constants (`FACTION_BIOMES`, `BIOME_COND_FACTION`) are asserted equal to the engine's in the test suite.
- **#20 VERIFIED + DOCUMENTED** — no projection code is needed: `Celestial_reversal` / `thermic_flux` are **INSTANT** (applied at play time) and `update_player_state` re-reads temperature/day_night from a FRESH game object every tick, so any card scored later in the same turn already sees the post-change state — by me or the opponent.
