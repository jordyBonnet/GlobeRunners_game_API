### Support factions (second deck, menu selection)

- Data: `cards/support_factions.parquet` — 15 cards across 3 support factions (Engineers, Mages, Doctors; 5 unique each). Columns: `support_faction_name`, `card_name`, `mana_cost`, `description`, `card_path` (art file name, e.g. `Mag_black_hole.png`).
- **Deck composition since 2026-09**: a player's deck = **20 main-faction cards** + **10 support cards** (2 copies of each of the 5 unique support cards) = **30 cards, shuffled together** (the UI shuffles before sending). Support card ids in the deck are the `card_name` values (e.g. `black_hole`) — they are **not** in `cardpool.parquet`.
- **Art**: support card art is served at `/art/<card_path>` (e.g. `/art/Mag_black_hole.png`) — **not** `/art/<card_name>.png` (the file name differs from the card name, unlike main cards where file name = `card_id`). Frontend helper: `cardImg(id)` in `game_ui/static/cards.mjs`.
- **Engine**: **Engineers are implemented** — see *Engineers* below. **Doctors are implemented** — see *Doctors* below. **Mages are fully implemented**: **`Celestial_reversal`**, **`nobodymoves`**, **`thermic_flux`**, **`Apocalypticritual`** and **`black_hole`** (a **dwelling** card — see *Mages* below). Note: **every** support card (Mages included) **costs its `mana_cost`** when played (see `_play_cost`). Like the other support cards, the Mages cards are **not** in `ge.CARDS_DB`, so their `CARDS_DB.filter(is_in([id]))` lookups come back empty and the guards make the *trip-chain* part a no-op (advancing 0) — their **real effect** is applied by the engine (instant at play time for the 4 INSTANT cards; the dwelling TAP for `black_hole`), not by the trip chain. Do not "fix" the trip-chain no-op to an error — it is the correct behavior.
- **AI**: since A.1 ([player_ai/AI_improvement_list.md](player_ai/AI_improvement_list.md), ✅ 2026-09-21) `PlayerAI` **plays** support cards: main moves via the existing `play_card` path, everything else via `choose_support_play()` (drops/dwellings/pendings/mage instants — each with its required choice field, see *A.1*) and `tap_dwelling()` for the free quick-action taps (bookkept by the loop's `tapped_this_turn` flag). `put_mana` still considers the whole hand, but now ranks by **keep-value** (`_mana_keep_value`: mains = 18−mana; support = current play utility `_support_value`) — playable support stays in hand, dead copies (2nd dwelling with the zone full, a useless instant…) sink to the bottom. The init requirement is unchanged: exactly 3 cards into mana in one valid message when needed. The Robot's starter deck is 20 random main + 10 random support (`ai_driver.random_ai_deck`).
- **API**: `GET /support_factions` lists the 15 cards (banner images at `/art/supfac_{eng,mag,doc}_banner.png`); `check_deck` (API.py, public) validates decks that mix main `card_id`s and support `card_name`s — it also **rejects a deck containing the same main card twice** (a card can only appear once; support card names legitimately appear 2×). The frontend CSV import (`parseCsv` in `setup.mjs`) rejects duplicate ids with a clear toast before the deck is used.

### Engineers (support faction)

The **Engineers** support faction is fully implemented (the first of the three). Its 5 cards are: **4 drop cards** (boost, trampoline, gluetrap, landmine) + **1 dwelling card** (refinery). All support cards (engineers included) now **cost their `mana_cost`** when played (see *Support card cost* below).

**The 4 drop cards** (all `mana_cost` 1 except landmine = 3). Each is played in **MOVE mode** with a **target earth cell** (`message["cell"]`, 0-23). At **play time** (instant, like pet_trap/wrecking_ball — before the trip chain, so it **cannot be blocked, effect-canceled or conditioned**), a **drop token** is placed on that cell (`GameState.board_drops: [{cell, kind, owner}]`, public board info). The card itself then resolves as a **no-op** (only advances by its basic value; `effect_number` is 0 and unused). The FIRST token (either player) that **arrives** on the cell triggers the drop, then the token is **consumed**:

| Card (card_name) | mana_cost | Token image | Trigger when any token arrives on the cell |
|---|---|---|---|
| `boost` | 1 | `/assets/supfac_eng_boost.png` | Arriving token advances **+2** (step-by-step via `process_advancing`: win-check + can chain-trigger further drops, no biome bonus) |
| `trampoline` | 1 | `/assets/supfac_eng_trampoline.png` | Arriving token **jumps +2** (teleport via `_jump`, landing-cell check only) |
| `gluetrap` | 1 | `/assets/supfac_eng_slowingtrap.png` | Arriving token **knocked back −1** (direct, clamped at cell 0, no re-trigger) |
| `landmine` | 3 | `/assets/supfac_eng_mine.png` | Arriving player is **blocked for the rest of the turn**: `landmine_blocked = True` — their MOVE cards are **canceled** (no effect, no advancing) **except** an `unstoppable` card whose condition is met; DEFEND cards are unaffected. Cleared in the cleaning phase. Also **stops the remaining steps of the current movement** that just landed on it. |

- **Placement rules**: playing a drop requires the `cell` field (the engine rejects a drop without it). Placing it on a cell **already occupied** by a token does **not** activate it (it only fires on **arrival**). Multiple drops on the same cell fire **in placement order**; if a drop moves the token **off** the cell (boost/trampoline/gluetrap), the remaining drops on that cell **stay** (the position is re-checked before each).
- **Trigger sites**: `process_advancing` (every step) and `_jump` (landing cell) both call `_trigger_board_drops` after the pet_trap check. **Critical**: the earth re-sync (remove the player from all cells, append once at the final position) must run **BEFORE** `_trigger_board_drops`, because a boost/trampoline inside the trigger recurses into `process_advancing`/`_jump` — otherwise the recursive earth sync hits a `ValueError` (list.remove on an absent token).
- **Landmine gating**: `_player_blocked(player, game)` (and `landmine_blocked`) gates the move branch of `process_card` (cancels the card) and both grappling-hook and copy_effect copies in `process_trip_chain`. The `was_blocked` flag is captured before the movement loop so a landmine fired **mid-movement** breaks the current move but doesn't re-fire on the stale flag.
- **Replay**: `_replay_trip_chain` mirrors the instant drop placement (reads `message["cell"]` + the card for `ge.ENGINEER_DROPS`), the dwelling placement/tap (hand→dwelling, or `_pick_draw` + `ge._draw_cards`), and the landmine gates. The final **board_drops** and **dwelling** are compared to the stored ones (a warning on divergence). The final **dwelling** card is included in the conservation pool (it is not in any standard zone).
- **AI**: since A.1 the robot PLACES drops (move mode + chosen `cell`) and TAPS the refinery every turn (free quick action, once per turn via the loop's bookkeeping). Since **A.4** the targeting is path-aware (`_choose_drop_cell` around `_my_reach_cells()` / `_oppo_reach_cells()`, public info only): **boost/trampoline** prefer a cell of MY predicted path this turn (the estimates of my declared moves sum; else 1–6 cells ahead), skipping any cell the opponent reaches strictly sooner (they would consume it first — tokens only move forward, so a cell behind their token is always safe); **gluetrap/landmine** take the EARLIEST cell of the OPPONENT's predicted path (their declared potential advances, else a typical range 1–4 ahead) and are NEVER placed on my own predicted path, since whoever arrives first eats the drop. Occupied cells and cells already carrying a drop token are always skipped; a locked turn (nobodymoves / landmine block) empties my reach and ignores their declared moves. The value side matches (`_support_value`: +6 boost on my path this turn, +8 gluetrap on theirs, landmine 45/18 via `_oppo_finish_threat` — a declared winning move or cell ≥20 with cards in hand), so `put_mana` keeps live denial drops and sinks dead ones. The refinery goes down as soon as affordable (value 50, above every drop/pending/instant). `drops_on_board` (the `drop_on_board` condition) now also counts `board_drops`.
- **Frontend** (`game_ui/static/`): `ENGINEER_DROPS`/`isEngineerDrop`/`isEngineerDwelling` in `cards.mjs`. Playing a drop card enters **cell-selection mode** (24 clickable targets on the Earth ring, `#cell-targets` + `body.cell-selecting`), then sends the action with `cell`. Playing the refinery sends `to: "dwelling"`. A **Tap dwelling** button (`#btn-tap`) sends `mode: "dwelling_activation"`. Board drops render on the Earth (`.drop-token.eng-drop`), the dwelling card in the dwelling panel (dimmed via `.dwelling-tapped` when tapped), and a `💣 blocked` badge (`.landmine-badge`) appears on the blocked player's banner. `cardCost(id)` (in `cards.mjs`) handles support-card costs for the mana check.
- **Preview**: `tests/_engineers_preview.html` (copy into `game_ui/static/` and screenshot via headless Chrome, like `_drop_tokens_preview.html`).

**The dwelling card — `refinery`** (`mana_cost` 3). Placed in the **dwelling spot** (`PlayerState.dwelling`, a single card id, public board info) — **one at a time, permanent** until removed by a `wrecking_ball` (see *Wrecking ball*). The dwelling spot is now **placeable**: it is filled by playing the refinery (`to: "dwelling"`, 1 card, costs `mana_cost`), a **play-phase action** that alternates control like a normal play (not in the trip chain, not resolved by `process_card`). **Tap**: once per turn (`mode: "dwelling_activation"`, no cards, **free**) → the owner **draws 1** card; `dwelling_tapped` is set and reset in the cleaning phase (untapped every turn). Since 2026‑09 the **tap is a QUICK action** — it does **not** alternate control: the state stays "waiting for <this player> to play", so the tapper may still play a card or pass afterwards (the engine sets no state transition in the tap branch of `player_play`). Placing the dwelling still alternates like a normal play. 
**Dwelling placeholder** (UI feature). When a player places a dwelling card (refinery), a **faction-specific placeholder image** appears in the **stopover slot that the refinery would have occupied** if it were a normal play (determined by the play order at placement time via `ge._next_free_stopover`: the k-th action → the k-th **FREE** stopover — **SKIPPING any stopover reserved by board furniture**, e.g. a rooted-on-board card — so the placeholder never lands on top of another card). The slot is stored in `PlayerState.dwelling_slot` (0-4 column index), **set at placement time and cleared by the engine in the cleaning phase** (the per-player reset in `_end_turn`) — so the placeholder only shows during the placement turn and must **not** reappear at every new turn (the frontend renders it only while `dwelling_slot` is set; the `dwelling` card itself stays on the board). The placeholder is purely visual — it does not block, defend, or trigger any effect — but it **fills the slot** while shown so both players can see the dwelling card is on the board. The image is chosen by the player's main faction (`PlayerState.faction`, derived from the deck at game creation): `placeholder_Dwa.png`, `placeholder_Dem.png`, `placeholder_Twi.png`, `placeholder_Mia.png`, `placeholder_Orc.png`, `placeholder_Mum.png` (served at `/cards_ex/placeholder_<key>.png` from `GlobeRunners_card_system/lib/artdesign/cards_ex/`). The slot is also marked as "filled" (not dimmed) when it contains a dwelling placeholder. When a `wrecking_ball` removes the dwelling card, both `dwelling` and `dwelling_slot` are cleared. Frontend: `getFactionKey()` + `dwellingPlaceholderSrc()` in `cards.mjs`, `.dwelling-placeholder` class in `style.css`.

**Support card cost**: `_play_cost(current_game, card_id)` returns a main card's `mana` (from the pool) or — for a support card — its `mana_cost` (from `ge.SUPPORT_DB`). So **every** support card costs its `mana_cost` when played. The frontend mirrors this via `cardCost(id`).

**Tests**: `tests/_engineers.py` (16 tests: cost, drop placement, no-cell rejection, boost/trampoline/gluetrap/landmine triggers, landmine block/exception/cleaning, dwelling place/tap, wrecking ball, drop_on_board, full kept game with conservation).

### Doctors (support faction)

The **Doctors** support faction is fully implemented (the second of the three). Its 5 cards are: **4 pending cards** (epo, virus, bloodtest, mercurochrome) + **1 dwelling card** (laboratory). All support cards (doctors included) **cost their `mana_cost`** when played.

**The dwelling card — `laboratory`** (`mana_cost` 3). Placed like the refinery (`to: "dwelling"`, 1 card, costs `mana_cost`, placeholder in the stopover, one at a time until removed by a `wrecking_ball`). **Tap**: once per turn (`mode: "dwelling_activation"`, no cards, **free**) → the owner gets an **`epo` pending card** added to their pending zone (attachable to a main card like any other pending card — see above). **The tap is a QUICK action (like the refinery tap — no alternation, the state stays "waiting for <this player> to play") and the tap's `epo` creates NO trip-chain placeholder**: it goes into the persistent `pendings` zone but consumes **no position** (`play_count` untouched) and gets **no placeholder** (`pending_slots` is the per-turn `[card, slot]` pair list). `ge._player_chain` skips it (a grappling/copy facing that position faces the play behind it) and the frontend never renders a placeholder for it.

**The 4 pending cards** (all `mana_cost` 1 except mercurochrome = 2). Each is played in the **pending zone** (`to: "pending_zone"`, 1 card, costs `mana_cost`). The card is removed from the hand and added to `PlayerState.pendings` (a list of card names, public board info — **persistent**: the card stays in the zone until attached to a main card). A **placeholder** is created in the stopover, stored in `PlayerState.pending_slots` — the **per-turn placeholder display list** (cleared in the cleaning phase, like the dwelling placeholder, so the placeholder only shows during the placement turn). **Each entry is a `[card_name, slot]` PAIR**. The pair matters: `pendings` is **persistent** but `pending_slots` is **cleared every turn**, so the two lists are **NOT parallel** from turn 2 on — attachment therefore handles the placeholder **by card name** (the first matching pair), never by index in `pendings` (index-based splicing could delete the **wrong** placeholder). **The placeholder of a pending card attached the SAME turn STAYS IN PLACE**: it marks the trip-chain position the pending placement consumed, so the next play lands one position further and the frontend's next-slot mirror (visible `action_chain` + placeholders) stays consistent with the engine's `play_count`.

**Attachment**: when playing a **main faction card** in **move mode**, the player may attach **at most 1** pending card (`pendings: [card_name]` in the message). The engine validates: the pending card must be in the player's `pendings` zone, the main card must be a main card (not a support card), and the mode must be `"move"`. On success, the pending card is **consumed** from the zone and stored as `player.message['pending_card']`. The placeholder of an attached pending card that was **placed the same turn** **stays in its stopover slot** (the `[card, slot]` pair remains in `pending_slots` until the cleaning phase — it marks the consumed trip-chain position; the tooltip says "attached"). An **old** pending (placed a previous turn) has no placeholder either way.

**Effect**: the pending card's effect fires **only if the main card's condition is met** (and its effect was not canceled by `effect_canceled`). The effect is applied via `_apply_pending_effect()` after the main card resolves:

| Card (card_name) | mana_cost | Effect (when attached to a main card whose condition is met) |
|---|---|---|
| `epo` | 1 | **+1 advancing** (applied via `process_advancing(1, allow_bonus=False)` — no biome bonus) |
| `virus` | 1 | **−1 knockback** (applied via `process_advancing(-1, allow_bonus=False)`, clamped at cell 0) |
| `bloodtest` | 2 | **The OPPONENT discards 1 card** — treated exactly like the main-card `discard_oppo` effect: the trip chain **pauses** (`"turn N - waiting for NAME to discard 1 card(s)"`), the **opponent CHOOSES** the card (sends it with `to: "discard_pile"`), and the chain resumes. The attaching player's own hand is never touched (bug fixed 2026-09-22 — see *Discard selection* in [cond_effects_agent.md](cond_effects_agent.md)). Opponent hand empty → no-op (a note is logged, no pause). |
| `mercurochrome` | 2 | **Unstoppable** (passive modifier: the main card ignores defend blocks and landmine blocks — checked at block time in `process_card` via `_is_unstoppable`; no separate `apply_effect` call) |

- **Gating**: the pending effect fires only when `effect_activated` is True (condition met + not blocked + not `effect_canceled`). A blocked or not-met main card → no pending effect.
- **Card conservation**: the pending card is moved to the discard pile in `process_card` (after the effect is applied). On a mid-chain win, `flush_unresolved` flushes the attached pending card to the discard.
- **AI**: since A.1 the robot places pending cards (`to: "pending_zone"`, 1 card, costs its `mana_cost`) and places/taps the laboratory (free tap → +1 generated `epo` per turn; exactly one tap per turn via the loop's bookkeeping). Since **A.2** it also ATTACHES pendings to its main move plays (`_choose_attachment`, [AI_improvement_list §A.2](player_ai/AI_improvement_list.md)) — only when the pending effect can actually fire (its own condition met, no facing valid move-mode `effect_canceled`): **mercurochrome** buys unstoppable against an opponent shield block on its facing stopover, a landmine drop on its path, or this turn's movement lock; **epo** (+1) attaches when it completes the win (`pos + estimated advance == 23`) or as tempo while it has a laboratory / ≥2 pendings in zone (keeps one for the `pending` condition); **bloodtest** (now an opponent-targeted discard, worth 18 vs the old self-penalizing 16) attaches when the effect can fire, the play would not be blocked and the opponent's hand is ≥1 (it also keeps ≥1 pending in the zone while holding `pending`-condition main cards). **virus** is still never auto-attached (−1 knockback to myself — self-penalizing). The facing stopover is mirrored from public info only (its own rooted tokens on board + its `play_count`, like `ge._player_stopover`), and the opponent's declared shields come from their PUBLIC `action_chain`.
**Replay**: `_build_initial_state` includes `pendings` in the conservation pool. The play phase mirrors pending zone placement (hand → pendings + pending_slots as `[card, slot]` pairs). The dwelling tap branch handles the laboratory tap (adds an `epo` pending card instead of drawing — no slot entry). The pending card is removed from the zone when attached to a play (mirroring the engine's `player_play` consumption; the placeholder pair stays in place). `_process_action` calls the real `ge.process_card` which applies the pending effect and flushes the card to discard. The flush_unresolved mirror includes the pending card. A `bloodtest`-set `pending_discard` is consumed by `_process_action` right after `process_card` (it applies the choice via `_pick_discard` from the opponent's reconstructed hand — the real player's `discard_pile` message is already in the history and is skipped from the chain, like every discard choice). **Turn segmentation** (`segment_history`): a per-turn mana message is a turn boundary iff it is a mana PLACE (`to: "mana"`) or a recorded PASS — PLAY-PHASE passes are never recorded by the engine (the pass branch of `player_play` returns before the history append), so a recorded `mode: "pass"` message is by definition a mana-phase pass. The replay also mirrors the engine's `_end_turn` per-player resets (notably `pending_slots = []` / `dwelling_slot = None` — a stale placeholder keeps a phantom entry in `ge._player_chain` that shadows the play at the same position).
- **Frontend** (`game_ui/static/`): `DOCTOR_PENDING`/`DOCTOR_DWELLING`/`isDoctorPending`/`isDoctorDwelling` in `cards.mjs`. Playing a pending card sends `to: "pending_zone"`. Playing the laboratory sends `to: "dwelling"`. Playing a main card with pending cards available shows a **popup** to select a pending card (or skip). Pending placeholders render in the stopover slots (`.pending-placeholder` class, gold border). The pending zone renders in the side panels (`my-pendings` / `oppo-pendings`).
- **Tests**: `tests/_doctors.py` (test groups: pending zone placement, epo attachment, laboratory tap, **attachment-must-not-wipe-unrelated-placeholder**, mercurochrome unstoppable, **same-turn attachment keeps the placeholder in place**). `tests/_doctors_bloodtest.py` (27 checks: the pause targets the **opponent** — the attaching player's hand is untouched (the regression check), only the opponent's exact choice is accepted (caster / wrong count / not-in-hand all rejected), the chain resumes and conservation holds, the log note names the discarding opponent, empty opponent hand → no-op branch; deletes its own games).

### Mages (support faction)

The **Mages** support faction is **fully implemented** (the third of the three support factions). Its 5 cards are: **`Celestial_reversal`** (INSTANT) + **`nobodymoves`** (INSTANT) + **`thermic_flux`** (INSTANT) + **`Apocalypticritual`** (INSTANT) + **`black_hole`** (a **DWELLING** card). All support cards (Mages included) **cost their `mana_cost`** when played. The 4 INSTANT cards fire at play time (like an engineer drop — cannot be blocked/canceled/conditioned); `black_hole` is a **dwelling** (placed in the dwelling zone, its effect fires on a **TAP** — like the refinery/laboratory).

**`Celestial_reversal`** (`mana_cost` 2). An **INSTANT** card (like an engineer drop / pet_trap / wrecking_ball): the effect fires **at play time** (inside `_apply_instant_effects`, right after a successful **move-mode** play) — **before** the trip chain resolves, so it **cannot be blocked, effect-canceled or conditioned**. The card itself then resolves in the trip chain as a **no-op** (it is a support card, so its `CARDS_DB` lookups for condition/effect/advancing come back empty and the guards make it advance 0 — it effectively sits on the trip chain like a placeholder). A `Celestial_reversal` played in **defend** mode is a plain no-op (no day/night choice, no instant effect).

**The effect** (the instant part):
- **Fixes the planet's day/night** to the value the player chose (via a **popup** — Day or Night), **for the rest of the game**.
- Normally the day/night flips every turn (day ↔ night) in the cleaning phase. Since `Celestial_reversal` is played, the flip is **skipped** for the rest of the game: `GameState.day_night_fixed` is set to `True` and the flip branch in `_end_turn` is gated on `not day_night_fixed`.
- The player's choice is sent as **`message["day_night"]`** (`"day"` or `"night"`) — validated by `message_check` (must be one of the two) and required by `player_play` for a `Celestial_reversal` move play (a move play without `day_night` is **rejected**).
- **Day/night matters** for the `day`/`night` conditions: a player who fixes *night* makes all `night`-condition cards met and all `day`-condition cards not-met for the rest of the game (and vice versa). So it is a strong, permanent tactical lever.
- The turn log records a note on the card's line: `🔮 Celestial_reversal — day/night fixed to <day|night>` (kept short — the permanence is part of the card spec, not repeated in the log).
- **Card conservation**: the card leaves the hand at play time and resolves to the discard as a no-op (advancing 0) — no special handling needed (the standard move-card flow).

**AI**: since A.1 the robot may play Celestial_reversal; **since A.3** `_choose_day_night` weights by VALUE instead of raw counts — each own day/night-condition main in hand+deck contributes its condition delta (`advancing − (mana−1)`), so a handful of junk phase cards no longer outvote one valuable one. It plays only when the preferred phase strictly beats the current one and would actually change something (already fixed to its preference, or both phases neutral → keeps the card). `_condition_met` re-reads `game.day_night` every tick, so once either player has played it the robot automatically evaluates against the fixed phase — no extra work.

**Replay**: `_replay_trip_chain` mirrors the instant effect: it reads `message["day_night"]` from the Celestial_reversal play, sets the local `day_night` + `day_night_fixed` + `game.day_night`, and records a `celestial_reversal` event. The end-of-turn flip is gated on `not day_night_fixed` (the replay mirrors the engine's skip). The replay's `_card_row` synthesizes a support row for Celestial_reversal (advancing 0, no condition/effect) so the trip-chain no-op resolves cleanly (no "unknown card" warning).

**Frontend** (`game_ui/static/`): `MAGE_CELASTIAL_REVERSAL` / `isMageCelestial` in `cards.mjs` (added to `isSupportPlay`). `showDayNightPopup` in `actions.mjs` (a Day/Night modal, reusing the `.pending-popup` styles) — playing a Celestial_reversal card opens the popup, and the chosen value is sent as `day_night` in the action. `sendAction` in `comm.mjs` accepts a 6th `dayNight` param (sent as `msg.day_night`). The `dispatchPlay` branch order is: engineer drop → engineer dwelling → doctor pending → doctor dwelling → **Mage Celestial_reversal** → normal move card. See `game_ui/static/app-js-overview.md`.

**Tests**: `tests/_mages_celestial.py` (31 engine-level checks: fix to day/night, persistence, `day`/`night` condition eval, rejection without `day_night`, defend no-op, pending-attachment exclusion, log note), `tests/_mages_celestial_e2e.py` (14 checks through the real `handle_websocket_message` entry point with `model_copy()`), `tests/_mages_celestial_replay.py` (8 checks: the replay mirrors the day/night fix — turn 1 fixed, turns 2+ do not flip, no unknown-card warnings, event recorded). All delete their own games.

**`nobodymoves`** (`mana_cost` 3). An **INSTANT** card (like an engineer drop / pet_trap / wrecking_ball / Celestial_reversal): the effect fires **at play time** (inside `_apply_instant_effects`, right after a successful **move-mode** play) — **before** the trip chain resolves, so it **cannot be blocked, effect-canceled or conditioned**. The card itself then resolves in the trip chain as a **no-op** (it is a support card, so its `CARDS_DB` lookups come back empty and the guards make it advance 0). A `nobodymoves` played in **defend** mode is a plain no-op (no lock effect). `nobodymoves` is also **excluded from doctor pending attachment** (like all support cards) and from the **defend button** in the frontend (it is a move-mode card).

**The effect** (the instant part) — **LOCKS ALL PLAYERS' MOVEMENT for the rest of the turn** (it does NOT cancel the cards):
- `GameState.nobodymoves_active` is set to `True`. From that moment until the end of the turn, **every player's MOVE cards still RESOLVE** (the condition is checked, and **non-movement effects still fire** — `draw`, `ramp`, `discard`, `taxation`, the `rooted` token, `effect_canceled`, …) and **the defend/block race still happens**, but their **MOVEMENT is suppressed**: no basic advancing (normal or reduced), no movement effects (`advancing`/`backward`/`jump`/`advancing_oppo`/`backward_oppo`/`avalanche`), no pending `epo`/`virus`, and no grappling-hook / copy_effect copies of a movement effect. **Exception**: an `unstoppable` card whose condition is met **still moves** (the same exception as the landmine block). DEFEND cards are **unaffected** (they never advance; they just contribute their shield to the block race). The **cataclysm trigger's knockback** is also a suppressed movement — the trigger still fires (the pile rotates and the biome is announced) but **no token is knocked back** (see *Cataclysm*).
- The lock is **global** (both players) — unlike the landmine, which is per-player **and** cancels the card. It is checked in `_is_movement_locked` (nobodymoves active + the card is not unstoppable), which gates the basic advancing + movement effects in `_resolve_card`, the pending `epo`/`virus` in `_apply_pending_effect`, and the grappling-hook / copy_effect copies in `process_trip_chain`. (`_player_blocked` is kept for the **full-cancel** landmine and for **rooted cards** on the trip chain — a rooted card is pure movement, so it is inert during a nobodymoves turn.)
- The lock is **cleared in the cleaning phase**: `_end_turn` resets `nobodymoves_active` to `False` at the end of the turn (the same place that clears the landmine block). So the lock lasts exactly one turn.
- **Consequence**: no player can advance (and thus no one can win) during a nobodymoves turn, unless they play an `unstoppable` card whose condition is met.
- The turn log records a note on the card's line: `🚫 nobodymoves — all players' movement locked`, and a per-card note `🚫 nobodymoves — movement locked` on each locked card's line.
- **Card conservation**: the card leaves the hand at play time and resolves to the discard as a no-op (advancing 0) — no special handling needed (the standard move-card flow).

**AI**: since A.1 the robot may play nobodymoves as a THREAT response (`play_nobodymoves_threat` — only before it has committed its own move this turn). **Since A.3** the trigger is a three-part public estimate (`_nobodymoves_threat`): (a) SELF-DENY guard first — if an affordable main in its own hand could win this turn it never locks itself out; (b) DECLARED threat — each of the opponent's unresolved move plays (public `action_chain`) is scored with `_oppo_potential_adv`, which evaluates the card's condition from public info via `_oppo_condition_eval` (day/night, temp_*, biome_X at their cell, dist_* from THEIR perspective; unknown → worst case for me) and subtracts my declared shields on the facing stopover — except an `unstoppable` whose condition is provably met ignores the block; (c) LATENT threat — `_min_win_cost(need, bonus)` (precomputed over the full pool: cheapest card that could cover the remaining distance, with/without biome bonus) vs the opponent's VISIBLE spending power this turn (its public `mana` count minus its declared mana_spend). The same estimate feeds the keep-value, so a held nobodymoves survives init/mana sacrifice while the threat is live. When it does play, `nobodymoves_active` binds the ROBOT TOO: its own movement cards are suppressed that turn (unstoppable+met excepted) — exactly like for a human.

**Replay**: `_replay_trip_chain` mirrors the instant effect: it detects a `nobodymoves` move-mode play in the play loop, sets the local `nobodymoves_active` to `True`, and records a `nobodymoves` event. The local flag is reset to `False` at the end of each turn (mirroring the engine's cleaning-phase reset). The replay's `_card_row` synthesizes a support row for nobodymoves (advancing 0, no condition/effect) so the trip-chain no-op resolves cleanly (no "unknown card" warning).

**`Apocalypticritual`** (`mana_cost` 3). The pile is the **cataclysm rotation** (see *Cataclysm*): index 0 is the biome that **strikes next** (when a `cataclysm`-condition card resolves, the top biome strikes, then rotates to the bottom). So the player is **choosing which biome strikes first** (and the full subsequent order), **PERMANENTLY** until the next `Apocalypticritual` (the pile is a pure rotation — it is never exhausted, only rotated by each strike — so the chosen order stays until another ritual overwrites it). This is a strong tactical lever: the player can line up a favorable biome to strike the opponent's token, or delay an unfavorable one.
- The turn log records a note on the card's line: `☄️ Apocalypticritual — cataclysm order set: A → B → C → D` (the 4 biomes in the chosen order, joined by ` → `). The replay parses this exact note to detect a ritual during the pile reconstruction (see *Replay* below).

Shared biomes resolve by depth (park it last only when I sit deeper than the opponent), empty biomes and segment position fall out of the same formula; the robot plays only on strict improvement over the current pile.
- **Replay**: this is the trickiest Mages card for the replay, because a ritual **breaks the pure-rotation invariant** the old pile reconstruction relied on (the old code rewound the stored final pile by the number of strikes — which is only valid when the pile is a pure rotation). The new `_build_initial_state` handles both cases: it parses the log chronologically for **strike** events (`⚡ cataclysm — <biome> strikes`) and **ritual** events (`☄️ Apocalypticritual — cataclysm order set: …`). If the game has **no** ritual, it uses the original rewind (rotate the final pile right by the number of strikes). If it **has** a ritual, it reconstructs the **initial pile** (`P0`) as: the biomes struck **before the first ritual** (in strike order) + the remaining biomes (in `BIOMES` order) — the strikes before a ritual pin the initial prefix, and the biomes after the last strike (before the ritual) are unobservable but valid (the ritual overwrites them immediately, so they never matter). At the end of the replay, the tracked final pile is compared to the stored `cataclysm_pile` (a `cataclysm pile diverges` warning on mismatch). The replay's `_card_row` synthesizes a support row for `Apocalypticritual` (advancing 0, no condition/effect) so the trip-chain no-op resolves cleanly (no "unknown card" warning).

**`black_hole`** (`mana_cost` 3). A **DWELLING** card (like the Engineers' `refinery` and the Doctors' `laboratory`) — **NOT** an instant-at-play card. It is **placed** in the dwelling zone (`to: "dwelling"`, 1 card, costs its `mana_cost`, one at a time until removed by a `wrecking_ball`) and its effect fires on a **TAP** (`mode: "dwelling_activation"`, `to: "dwelling"`, no cards, **free**, once per turn — `dwelling_tapped` set on the tap, reset in the cleaning phase, the same as the refinery/laboratory tap).
- **The TAP effect — rotate the earth**: the player **CHOOSES the direction** (a **CW or CCW** frontend popup — `showBlackHoleRotationPopup` in `actions.mjs`). The choice is sent as **`message["rotation"]`** (`'cw'` or `'ccw'`) — validated by `message_check` (must be one of the two) and **required** by `player_play` for a `black_hole` tap (a `black_hole` tap without a `rotation` is **rejected** — while the refinery/laboratory taps carry no `rotation` and stay valid, since they are not black_holes). The engine then calls **`ge.rotate_earth(current_game, ±3)`**:
  - **The 4 biomes SHIFT POSITION** in `gs.earth`: the biome codes at `earth[i][0]` rotate by 3 cells. **Clockwise** (`'cw'`) = `new[i] = old[(i − 3) % 24]` (the biome at cell i moves 3 cells toward the next index — the "top" biome moves toward the 3 o'clock position); **counter-clockwise** (`'ccw'`) = `new[i] = old[(i + 3) % 24]`.
  - **ALL TOKENS STAY on their own cell index**: both players' `current_position`, the pet_trap `drop_tokens`, and the engineer `board_drops` are **unchanged** (keyed by cell index). A rotation changes **which biome a given cell belongs to**, not where the tokens are. So after a rotation, the same cell can be a different biome (a player standing there may now be on a different biome, which changes their `biome_*` conditions and the +1 faction biome bonus).
  - The rotation is **CUMULATIVE** and **PERMANENT** (game-level state, not a per-turn flag): `GameState.earth_rotation` (signed cumulative cells, e.g. `+3` after one CW tap, `−3` after one CCW, `+6` after two CW) records it; 8 distinct states (24/3 = 8) before it cycles back. It is **not** reset in the cleaning phase (only `dwelling_tapped` is) and **persists even if the black_hole dwelling is later wrecked** (the rotation is a game-level state, independent of the dwelling card's existence).
  - `GameState.earth_initial_b0` records the biome of cell 0 **at game start** (set in `create_new_game`, never changed) — so the **frontend** can pin its background art to the initial order and **rotate it** by `earth_rotation × 15°` (the board geometry: `POS24[i] = polar(-90 + (i+0.5) × 15°, 49)` — 15° per cell) instead of swapping images. The **cataclysm pile is independent** of the earth rotation (it is its own rotation of biomes, struck wherever that biome is on the board).
- The card itself is a **no-op on the trip chain** (it is a dwelling, not played in move/defend mode — it sits in the dwelling zone). The tap is a **quick action** (like the refinery/laboratory tap — no alternation, the state stays "waiting for <this player> to play", so the tapper may still play a card or pass afterwards).

- **AI**: since A.1 the robot can place and tap a black_hole dwelling like any other; **since A.3** the tap direction is chosen by `_choose_rotation`, which scores cw vs ccw by (i) the faction-biome bonus each token keeps after the rotation (my bonus worth 2×, opponent's subtracted) PLUS (ii) `0.5 × _biome_cond_weight(biome under my NEW cell)` — the value delta of every own `biome_X`-condition main in hand+deck that would become met/unmet at the landing cell (`BIOME_COND_FACTION` maps each biome to its faction), so a direction that meets my biome-condition mains can outweigh the raw bonus. - **Replay**: `_build_initial_state` reconstructs the **initial earth**: it computes the **total rotation R** (the signed sum of every `black_hole` tap delta in the message history, `±3` per tap, mod 24) and reverses it — `initial[i] = final[(i + R) % 24]` (the engine's CW rotation is `new[i] = old[(i−n) % 24]`, so the inverse is a +R shift). The replay's `_card_row` synthesizes a support row for `black_hole` (advancing 0, no condition/effect) so any residual trip-chain reference resolves cleanly.
