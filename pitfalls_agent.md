## Known pitfalls

- `tests/_diag.py` **writes to `games.db`** — do not run it against a precious database.
- Art/assets folders: **hard-coded external paths** (`GlobeRunners_card_system/lib/artdesign/…`) with a placeholder fallback — do not "fix" the paths without verifying the fallback still works.
- A player's deck is just a list of ids from the Parquet pool — do not invent fields outside the Parquet columns.
- **All 22 `effect` values** of the pool are now implemented (the last one, `swap_cards` — see *Swap cards*). The only **unimplemented** rules left are the 2 conditions `face_point_left` / `face_point_right` (currently treated as **met** — the canonical unimplemented default — and **excluded from new games** via `ge.EXCLUDED_CONDITIONS`; see *Conditions*). Do not assume unimplemented conditions work.
- **Rule versioning**: `GameState.engine_version` records the rules a game was played under (currently the string `"1.0"`). **Every** current rule is active for every new game — all 22 `effect` values, all implemented `condition`s, the +1 faction biome bonus, the conditional block-card effect, discard selection, per-player stopovers, board-furniture placeholders, and the three support factions (Engineers / Doctors / Mages). There is **no legacy version gate** left in the engine, the replay or the AI: the code always applies the current rule set (see [cond_effects_agent.md](cond_effects_agent.md) and [sup_fact_agent.md](sup_fact_agent.md)). `games.db` is a fresh database — there are no old-version games to pin or migrate.
- **Replay self-test skips in-progress games** whose state is `turn N - waiting for … to play` (an unresolved trip chain can never verify against a full-history replay). The replay also keeps `game.day_night` in sync every turn — `day`/`night` conditions must evaluate against the turn parity, not a frozen "day".
- **Replay mid-chain-win semantics must mirror the engine exactly**: the engine checks the game state **before every action and after every grappling/copy step** and returns immediately on a win. The replay (`_replay_trip_chain`) enforces the same: no action, grappling copy, or copy_effect fires after a win, and the unprocessed played cards are flushed to their owners' discard (mirroring the engine's `flush_unresolved`). A win *during* a grappling copy still counts (the copy is what won). If you add a new post-action step to `process_trip_chain`, mirror its game-over ordering in the replay.
- **Replay card conservation for old games**: a few OLD games (created before the `flush_unresolved` fix) are missing their unprocessed played cards from all final zones — `analyze_game` reconstructs them in the discard before replaying (one-off historical artifact; the current engine conserves every card).
- **Replay (per-player stopovers)**: the replay's `_replay_trip_chain` mirror (a) builds per-player chains via `ge._player_chain` (rooted cards at the leading positions), (b) iterates by **position** (1..max), and (c) resolves rooted entries via `ge.process_rooted_card` (and play entries via the existing `_process_action`), with the grappling/copy/flush stages adapted to positions. The `_process_rooted_action` helper calls `ge.process_rooted_card` (basic advancing only, blockable). The copy stage requires `kind == 'play'` on both facing entries (a rooted card never copies). Multi-turn games with active rooted cards on the board now **verify clean** (see `tests/_rooted_v15_replay.py` — a 2-turn game with a rooted card advancing on turn 2, replay `verified=True`). Single-turn games also verify clean. **No known limitation** as of 2026-09-17.
- **Replay turn segmentation relies on what the engine RECORDS** (`segment_history`, found + fixed 2026-09-22 while fixing `bloodtest`): the engine records a player's message in `messages_history` for every accepted action EXCEPT **play-phase passes** (the pass branch of `player_play` returns before the history append). So a recorded `mode: "pass"` message is by definition a **mana-phase** pass (turn boundary), and a `to: "mana"` message is a mana PLACE (also a boundary) — `segment_history` treats both as the per-turn setup. The engine accepts a pass with ANY `to` (the frontend sends `to: ""` for every pass), so do **not** re-introduce a `to == "mana"`-only boundary test, and do **not** assume play passes are in the history. The replay's end-of-turn block must also mirror the engine's `_end_turn` per-player resets — notably `pending_slots = []` and `dwelling_slot = None`: a stale placeholder keeps a phantom entry in `ge._player_chain` that shadows the play at the same position (the play is silently never resolved).
- The engine does **not** verify that the message sender is the player whose action the state expects (branching is on `state` only) — the WS layer trusts the `player_name` from the URL. Treat out-of-turn senders as a known gap, not a rule.
- **Faction for biome rules is derived by MAJORITY VOTE over all card zones** (`ge._player_faction`: deck+hand+mana+discard; support cards aren't in the pool and don't count) — `PlayerState.faction` (set once from the first main card at game creation) can DISAGREE with it for mixed decks. Decks are single-faction by design, so they agree in real games; but **smoke tests that build scripted decks must keep them single-faction** or the biome bonus / `biome_*` conditions evaluate against an unexpected faction (found 2026-09-21 while writing `tests/_ai_a2_doctors.py`). The AI mirror (`PlayerAI._move_estimate`) reads `player_state.faction`, which is correct for single-faction decks.
